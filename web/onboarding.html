Set up the net worth page

Every visitor signs in to Sure with their own account and sees their own family's numbers. This server stores no data and no keys; it only needs to know which OAuth client to use.

  1. Create a read-only OAuth client in Sure

    Sure's OAuth application admin is open only to the instance's super_admin (the account that set Sure up), not to family admins. Open it and fill in:

    NameNet worth allocation
    Redirect URI
    Confidentialunticked — the page is a public client using PKCE
    Scopesread

    This address is neither https nor loopback, and Sure only redirects to those. Reach this page at the address users will use, behind TLS, before creating the client.

    Open Sure's new-application page

    After you save, Sure shows the client's UID. That is the client id.

    Not the instance's super_admin?

    Anyone can register a client, but Sure grants it read_write only. The page asks for read, so sign-in fails with “The requested scope is invalid” until someone with access to the Sure server narrows the client, or you set SURE_OAUTH_SCOPE=read_write and accept a write-capable token.

  2. Check the client id

    Paste the UID and check that Sure knows it.

  3. Configure and restart

    Set the client id and restart this server. This page is then replaced by the Sure login.

  4. Optional: map accounts to asset classes

    Sure has no asset class on accounts or securities, so accounts fall back to their type (depository → Cash, investment → Equities, …). A JSON file named by NETWORTH_MAPPING assigns classes, splits brokerage cash and nets loans against what they financed. It is re-read whenever it changes — no restart.

    {
  "accounts": {
    "Broker bonds":  { "class": "Bonds", "cash": "split" },
    "Pension":       { "class": "Pension" },
    "Flat":          { "class": "Property" },
    "Current":       { "class": "Cash", "group": "Current accounts" }
  },
  "netting": { "Mortgage": "Flat" }
}
